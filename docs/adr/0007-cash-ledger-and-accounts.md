# 资金是第三本账：流水是唯一真相，收付款单是唯一入口

**状态**：已采纳（2026-11-22，「资金账与账户」）

店里每个放钱的地方（现金、银行卡、微信、支付宝）是一本资金账：不可删改的带符号流水，余额 = 流水之和，现算、不落表。资金流水只有一个入口——收付款单（含退款）结算行的现金部分，1:1 生成；货品单上的「本次收款」经后台生成的收款单进入这本账。转账是一张带单号的单据，产出两条流水；手续费记在单据上，随转出账户一起减少。

## 考虑过的方案

- **账户上维护结存字段**：读得快，但余额成为第二份真相，任何一次只写一半都会永久对不上；调研的六家里没有一家把可编辑的结存放在账户档案上。
- **结存表缓存（照库存的做法）**：库存的结存表是成本链重放的必需产物；资金没有成本、没有重放，缓存只换来一处「缓存与真相不一致」的故障面。
- **货品单直写资金流水，或允许无单据的手工流水**：省一层转换，却造出「无源之钱」；对不上账时无法解释。
- **转账手续费单独成第三条费用流水**：账本上更「原子」，但把一次转账拆成转账与费用两件事，与六家厂商的做法都不一致；手续费记在单据上已可查、可汇总。
- **双余额口径（业务口径 / 出纳口径）**：星辰与 T+ 的能力，代价是两本账长期不一致、只能给用户一张排查清单；1-3 人店不需要。

## 后果

- 账户余额 = `SUM(cash_entry.amount)`；任何区间的期初余额 = 该区之前流水之和。报表首行显式给「期初」，不存「上期结转」。
- 资金流水只可红冲：改单 = 红冲旧版本 + 按新版本重开，两批都落原业务日期；作废 = 红冲；幂等键沿用 `doc:{id}:v{n}:…`。退款是业务单据（收款单 / 付款单的退款类型），不是红冲。
- 折让（抹零 / 让价 / 坏账）只改往来、不改资金：同一张收款单在往来侧结清，在资金侧只进现金。
- 转账单的两条流水满足「转出 = 转入 + 手续费」；手续费是单据字段，不产生第三条流水，也不设「差异」暗字段。
- 账户只停用、不删除；类型只有 现金 / 银行卡 / 第三方支付 / 其他，结算方式由账户类型承载（票 9 的 `doc_settle_line.method` 随之删除）。
- 余额允许为负，只红字提示、不硬拦；补记与垫付是真实路径，拦了等于逼用户乱录。
- 期初资金是一张带日期的期初单，每账户一条流水，落在启用日前一日；每账户只允许一条生效期初，后加账户另开一张期初单。
- v1 只出账户余额表与账户收支明细；资金日报、现金流量表、银行对账与账单导入留在规格之外。
