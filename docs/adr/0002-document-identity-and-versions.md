# 单据以单据号为身份、以版本为更正单位，账本只追加

**状态**：已采纳（2026-11-22，「单据生命周期与修改路径」）

用户眼里的一笔生意，在系统里自始至终只有一张单据、一个单据号。对它的一切更正都表现为追加新版本；账本上则是「红冲旧版本流水 + 按新版本重新过账」，两批流水都落回原业务日期。作废是版本链的终态，不是删除。草稿不占单号，生效那一刻才取号。

## 考虑过的方案

- **三张纸（原单 + 红冲单 + 新单，各有单号）**：审计最干净，也是多数国产进销存的形态。但 30 单 / 天的店按 10% 改单率算，一年堆出近千张废单，列表、对账单、客户沟通全被污染；更要命的是客户说的「XS20261119003 那单」会指向两三个单号。
- **静默改单（改了就是改了，不显示版本）**：最像 Excel，红冲留在后台。代价是同一单号在不同时刻内容不同，客户手里那张纸无从解释，出争议时没有可核对的东西。
- **按跨月设硬闸（未跨月才允许改，跨月只能红冲重开）**：照搬有总账、有凭证、有期间关账的系统。本系统把总账 / 凭证 / 期间关账全部列为 out of scope，ADR 0001 又已接受「往过去写就重放成本链、历史月份毛利会被改写」——日历这道闸在这里没有账务基础，只剩对「已交付物」的错觉。

## 后果

- 改单与作废都在账本上留下「红冲 + 重开」两组流水，且都落在原业务日期；净效果等于「这单一直长这样」。跨月改单因此会改写历史月份，报表必须显示最近一次重放时间（ADR 0001 已要求）。
- 「单号」不再标识一张纸，而是标识一笔生意。纸面上的区分靠版本号：第 N 版、已被第 N 版取代、作废水印。
- 决定「能不能改」的是下游引用（核销、退货、对账），不是日历；日历只负责一句二次确认。
- 已作废不可逆：要恢复只能新建一张单。
- 草稿不占号，因此丢弃草稿不产生断号；断号只剩「取号后事务回滚」一种可能，用数据库序列即可解决，不需要产品规则。
