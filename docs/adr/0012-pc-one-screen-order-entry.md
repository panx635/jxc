# 开单只做 PC 一屏键盘流，手机只读

**状态**：已采纳（2026-11-24，「开单动线与终端形态」）

店里的开单是柜台动作：一单从选客户到打印 2–3 分钟，约 30 单 / 天。决定把客户、明细、合计、收款放在同一屏，键盘优先；开单只做 PC，手机只做查询与看单。

## 决定

- **一屏编辑**：客户、明细、合计、收款同屏，不走向导、不做两步式。
- **检索顺序**：编码精确 / 前缀 > 规格词 > 名称 > 别名；空格 AND，最多 8 条。
- 明细行内显示规格与库存；「上次价」进弹层，不常显。
- **生效后直接进入打印预览**。
- 报价单与销售单共用编辑器，**一键转单并锁价**。
- PC 可开单；手机只读（单据、库存、欠款、报表），不做手机开单 / 接单 / 打印。

## 考虑过的方案

- **两步式（先选客户再录明细）**：省一次点击，但把一单拆成两屏，键盘流断掉。
- **向导式**：适合不熟练的录入；30 单 / 天的熟练工每一步都在等下一步。
- **手机竖屏作为 v1 开单入口**：店员在柜台用 PC，手机是老板在外面看数的工具；做手机开单要重做一整套布局与打印链路，换不来 2–3 分钟一单。
- **独立报价单模块**：报价单与销售单字段几乎相同，独立模块会让转单多一次复制；共用编辑器才能一键锁价转单。

## 后果

- 页面复杂度集中在一个编辑器里；键盘可达性、焦点顺序、快捷键成为验收项，不是视觉细节。
- 移动端只做查询，响应式布局只需覆盖只读视图。
- 打印入口固定在生效之后，用户不会在未生效单据上打印。
- 视觉定稿与真实打印不在本 ADR 内，归规格与实施票。
