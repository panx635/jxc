# 收款明细挂在货品单上，结算记录只有收款单一份

**状态**：已采纳（2026-11-22，「单据形态与字段」）

销货单上直接就能录「本次收款」（多账户、多行），保存时后台自动生成一张收款单并核销本单；用户只填一次，账上只有一份结算记录。退货单的「本次退款」按同一形状生成一张退款单。货品单上的收款明细是**输入**，收款单才是结算的**唯一真相**。

## 考虑过的方案

- **独立收款单（云星空形态）**：销售出库单没有收款字段，收款另开一张单再对源单核销。账最干净，但 1-3 人店的日常现金单会被迫开两张单——30 单/天里绝大多数是当场结清。
- **只在单据上记本次收款、不生成收款单（星辰 / 精斗云 / 管家婆形态）**：录入最快，但「一笔钱核销多张单」「提前收的预收款」无处落；往来模型需要一条能挂在单号上的核销记录。
- **单据上记 + 后台生成（T+ 形态）**：一次录入、账上一份可核销的记录。代价是同一笔钱有两个界面入口，改单时必须保证生成的收款单同步。

## 后果

- `doc_settle_line` 一张表两用：货品单上一行 =「从某账户收这么多、核销到本单」；收款单上一行 =「从某账户收这么多、核销到某张源单」。多账户、部分收款、预收、退款、1:N 核销共用这张表。
- 收款单生成后即为结算记录；改单导致金额变化时，核销额按「往来账、核销与对账单」的恒等式夹紧到当前金额，差额回未分配池，不另加搬运规则。
- 开单时的抹零不进结算行：它走**整单优惠**，改票面、改挂账金额；收款时的抹零是**收款折让**，进结算行的 `discount` 并必填原因。两者同名不同层，靠「发生在哪一步」区分。
- 作废一张带收款明细的货品单，同时冲销它生成的收款单；已核销到其他单的部分按往来票处理。
