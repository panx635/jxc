# 价格表用单层有序规则 + 必填兜底，不用客户等级 / 标准价三层

**状态**：已采纳（2026-11-22，「价格解析与折扣」）

每个客户直接挂一张价格表；表内是有序规则，最后一条是必填兜底。解析只读这张表，没有客户等级价格层，也没有商品标准价兜底层；参考进价与标准售价只是公式变量。旧三层（客户专属价 > 客户等级价 > 商品标准价）作废。

## 考虑过的方案

- **保留三层，把等级价做成表或折扣率**：客户专属、等级、标准价三层优先级浅显，但每加一个维度就多一层隐式回退；5000 SKU × 200 客户 × 3 档的维护量压不住，且「为什么是这个价」要跨三层解释。
- **客户 × 商品价格矩阵**：最精确，但价格单元数量爆炸；新品、调价、批量导入都变成日常负担，与 1-3 人店的第一约束冲突。
- **一客户多表、按优先级叠加**：灵活，但优先级本身又长成一套新的等级体系；同一客户的价格来源更难解释。

## 后果

- 每个客户必须有一张价格表；新客户默认系统「零售价」表，管理员可在系统设置里改默认表（只影响新客户）。
- 每张表必须有且只有一条兜底规则；兜底算不出就阻断，不静默回退到标准价或别的表。
- 改表影响所有使用该表的客户；单客户例外先复制为专用表，不叠加第二张表。
- 价格随参考进价 / 标准售价变化；历史单据靠行快照，不回改。
- 客户等级退出定价，改称「客户分组」，只做筛选 / 信用 / 报表。
- 公式只允许参考进价、标准售价、四则运算、括号、百分号；不用 eval，不允许函数 / 条件 / 跨表引用。
