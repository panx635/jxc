# 主数据扁平化：一个可售单元一条 SKU，别名做检索，换算挂商品

**状态**：已采纳（2026-11-21，「主数据与编码规则」；2026-11-22 与 2026-11-24 分别按「价格解析与折扣」「期初与数据导入」修订）

规模前提：常卖 5000 个 SKU、200 家客户。这个量级下没人翻得动分类树，只能搜。

## 决定

- 每个可售单元一条商品记录。规格是自由文本，**不做属性矩阵，也不做「商品 + 规格行」**。
- 商品字段：编码（自动流水号，可手工覆盖）、名称、规格、别名（多个）、品牌、一层分类（约 10 类）、基单位、包装单位及换算率（0..N）、参考进价、标准售价、税率、条码（可空，不启用扫码）、停用标记。
- 每个商品一个基单位加 0..N 个包装单位；换算率**挂在商品上**，不挂单位表；库存只按基单位记数量。
- 客户与供应商是扁平档案。客户可挂**客户分组**，只用于筛选 / 批量分配价格表 / 信用 / 报表，不参与定价（ADR 0003 已作废「客户等级价」）。
- 主数据只停用、不硬删；单据行保存名称、规格、单位、单价、税率的**快照**。
- 编码是导入的匹配键：商品按编码，客户 / 供应商按名称，期初库存按商品编码，期初往来按对象名称分组。
- 档案上不设「期初欠款 / 期初应付」字段——期初是启用日前一日的流水，不是档案字段（ADR 0009）。

## 考虑过的方案

- **属性矩阵（SPU + SKU）**：颜色 / 尺寸 / 材质组合出 SKU。五金没有统一属性体系（DN15、4 分、半寸混着叫），矩阵维护成本高于收益，且每加一种规格都要改结构。
- **商品 + 规格行**：规格独立成行，商品共用价格与库存。但库存、价格、一客一价都在可售单元粒度上，规格不独立成 SKU 会让账本碎掉。
- **条码 / 扫码优先**：需要给 5000 个 SKU 贴码，小店没有这套作业；条码字段留空备用，开单首屏是搜索框。
- **导入整批回滚**：5000 行里一行脏数据就挡住整批；改为逐行 upsert + 错误清单，部分成功。

## 后果

- 开单首屏是搜索框 + 常用清单，不是分类树；分类只服务报表分组与批量建档。
- 规格是自由文本，无法按规格做结构化统计或库存聚合；规格的规范化靠别名与搜索排序兜。
- 一客一价必须少而精，主力靠价格表规则（ADR 0003）；5000 × 200 的组合没人维护。
- 主数据改名 / 改价不影响历史单据。
- 导入是日常维护工具，不是一次性上线动作；上线先导 300–500 个常用 SKU，其余边卖边建。
