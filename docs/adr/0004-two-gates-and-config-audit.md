# 权限只设两道闸门，日志只记配置变更

**状态**：已采纳（2026-11-22，「权限与审计」）

1-3 人的店里没有审批者，老板几乎总在店里。系统只设两个角色（管理员 / 店员），仓管删除。角色与店员的差别只有两类：看不到成本类金额（账号级「看成本」开关，默认关），动不了配置（价格表、商品价、系统设置、账号）。开单、改单、作废、改价、收款全部对店员开放，靠「必填原因 + 首页当日清单」事后可见。日志只记配置与账号变更，单据动作交给版本链。

## 考虑过的方案

- **三角色（管理员 / 开单员 / 仓管）**：按十几人门店设计。单仓、没有独立仓管岗，进货与卖货是同一人，角色只会让建账号时多问一句，防不住任何具体损失。
- **单角色全员同权**：最省，但店员能看到进价与毛利——这是一次性、不可逆的泄露；配置改动也没有人能挡。
- **每用户勾选功能点**（管家婆、精斗云的做法）：厂商服务人更多的门店，权限点拆得细。1-3 人的店里 3 个账号 × 十几个勾选框，是一张需要解释的表；「店员」两个字比它好懂。
- **给改价设底价硬线**：低于底价必须管理员授权。它把成本投影成一条店员可见的线，但 5000 个 SKU 要有人填底价，而老板通常就在柜台边；且底价若由成本推导，会反向泄露成本。
- **全站操作日志**：记所有动作。单据已经有整单版本快照，再记一份会变成两份真相，也没有人看。

## 后果

- 店员的日常动作零闸门；唯一的硬差别是「看不见成本」和「动不了配置」。
- 成本保密用「入口收紧 + 单一出口过滤」实现：店员的菜单里没有采购、商品档案、价格表；所有响应按 `can_view_cost` 统一剥掉成本类字段，不在每个页面手写 if。
- 底价字段不做。改价 = 成交价 ≠ 解析价时二次确认 + 首页「今日让价」清单；「价格解析与折扣」§6 的底价行由本 ADR 修订。
- `audit_log` 只写配置与账号变更，只追加、应用层无改删接口、数据库收回 UPDATE / DELETE；不做日志查询页、不做登录日志。法规不要求单公司自用的进销存留业务日志：《网络安全法》现行第二十三条（原第二十一条）管的是网络运行状态与安全事件日志；《会计软件基本功能和服务规范》第三十二条只管生成凭证 / 账簿 / 报表的会计软件，而总账、凭证、期间关账在本项目 out of scope（依据见 research/roles-audit 分支的 `docs/research/2026-11-22-roles-audit.md`）。
- 权限变更立即生效，不需要重新登录。
- 如果将来做会计凭证 / 账簿 / 报表，要重新核对第三十二条的「按操作人 / 时间 / 内容可查」。
