**状态**：定稿（2026-11-24，wayfinder 票 #14）
**读者**：实现方（人或 agent），不需要读过前面 13 张决策票
**配套**：[GLOSSARY.md](../../GLOSSARY.md)（术语的唯一出处）、[docs/adr/](../adr/)（ADR 0001–0012，取舍的理由）、[v1-acceptance.md](v1-acceptance.md)（验收清单）

## 1. 范围与批次

### 1.1 产品形态

- 单公司自用、单租户的 Web 应用，云端部署；1–3 人使用，约 30 单/天、9000 单/年、十年 50 万流水、5000 SKU、200 客户。
- 单仓：数据模型保留 warehouse 维度，界面只开一个仓、**不显示**仓库选择。
- 开单只在 PC（一屏键盘流）；手机只读（单据、库存、欠款、报表）。
- 技术前提：TypeScript 全栈 + PostgreSQL。框架选型不属于本规格。

### 1.2 批次

| 模块 | P0（核心闭环） | P1 |
| --- | --- | --- |
| 主数据 | 商品、客户、供应商、价格表、资金账户 | 收支项目 |
| 单据核心 | 骨架、版本链、编号、状态机、幂等 | — |
| 业务单据 | 销售单、进货单、报价单、销售退货单、采购退货单、收款单、付款单 | 盘点单、日常收支单、转账单 |
| 三本账 | 库存账、往来账、资金账 | 盘点产生的调整流水 |
| 开账 | 三类期初单、五张导入模板 | — |
| 输出 | 四张报表、打印 | — |
| 权限与配置 | 两角色、看成本、三组可配、audit_log | — |

P1 与 P0 共用同一套骨架与账本。**在 P1 交付之前，账本不闭合**：账户之间的钱（转账）、非交易收支（房租工资）、库存差异（盘点）无处落账——上线检查表要求把 P1 的交付时间写进开账计划。

### 1.3 v1 不做

总账 / 凭证 / 科目 / 期间关账；发票与税控；多租户与计费；第二个经营主体与多账套；多仓 / 调拨；批次 / 效期 / 序列号；历史单据与历史凭证导入；独立送货单与配送状态；正式对账函 / 盖章确认；拖拽式打印模板设计器；PDF 归档 / 本地打印代理；逐联不同内容；58/80mm 小票；手机开单 / 接单 / 打印；银行 / 微信 / 支付宝账单导入、银行对账与余额调节表；资金日报与现金流量表；多币种；账龄桶自定义；生效期 / 未来价；一客户多表；返利与促销引擎；预收定向抵扣；坏账准备计提（只做坏账核销动作）；客商匹配对账；按明细行核销。

「后置」与「不做」有别：P1 是后置，规格已设计；本节是不做，本规格不设计。

### 1.4 性能与规模

- 报表一律实时查，不建汇总表、不建缓存。
- 明细分页 50 行；单张报表 p95 ≤ 1 秒；导出 ≤ 5 万行，超出提示缩小期间，不排队、不异步。
- 单商品平均约 100 条库存流水，成本链重放毫秒级，不做增量重放或后台任务。
- 索引至少覆盖：stock_movement(product_id, warehouse_id, biz_date, posted_at, id)、doc(doc_type, biz_date)、party_entry(party_id, biz_date)、cash_entry(account_id, biz_date)。

## 2. 角色、权限与配置

### 2.1 角色与账号

- 角色是枚举两个值：admin（管理员）/ clerk（店员）；不可自定义、不可叠加，一个账号一个角色。
- 管理员恒可看成本；店员 can_view_cost 默认 false，可由管理员逐个打开。
- 系统必须至少保留一个启用的管理员；最后一个管理员不能被停用或降级。
- 权限变更立即生效，不需要重新登录。
- 账号只能停用、不能删除；停用后不能登录，历史单据上的人名仍在。
- 登录：用户名 + 密码（Argon2id，退而求其次 bcrypt）；会话 30 天；忘记密码由任一管理员重置；不做短信 / 邮箱找回、MFA、登录日志。
- 1 人店里不出现「角色管理」页；账号页只有自己一行。

### 2.3 「看成本」管住哪些数

- **挡**：参考进价；实际成本（移动加权平均）；结存金额与成本单价；毛利与毛利率；价格规则试算里的「定价空间」。
- **不挡**：销售单价、销售额、库存数量、客户欠款、收款金额。
- 实现口径：**入口收紧 + 单一出口过滤**。店员的菜单里没有采购、商品档案、价格表、系统设置、账号；所有响应（含导出）按 can_view_cost 统一剥掉成本类字段，不在每个页面手写判断。
- 打印件**一律**不出现成本字段，不按「看成本」开关（纸一旦递出去就收不回）。

### 2.4 可配 vs 写死

只保留三组可配：

| 组 | 内容 | 生效范围 |
| --- | --- | --- |
| 店铺档案 | 名称、logo、地址、电话 | 全店，打印与页面抬头 |
| 打印模板 | 每张模板的字段显隐、列顺序、列宽档（窄/中/宽）、表尾文案 | 按模板；针式 6 行/页与 A4 流式固定 |
| 默认价格表 | default_price_table_id | 只影响之后新建的客户 |

其余一律写死：单仓、移动加权平均、含税录入 / 未税成本、两角色 + 看成本、单据类型与编号规则、账龄六桶、期初派生启用日、实时报表、四张表口径、成本过滤。

- 税率不做系统设置项：商品 tax_rate 必填，建档默认 13%；采购运费 freight_tax_rate 默认 9%（单据字段，无专票填 0%）。
- 可配项变更全部写 audit_log（action = settings.update）。

### 2.5 配置变更日志

audit_log 只记不落在任何一张单上的变更：

| 列 | 类型 | 说明 |
| --- | --- | --- |
| id | bigserial | |
| at | timestamptz | 服务器时间 |
| actor_id | bigint | 谁 |
| action | text 枚举 | 见下 |
| object_type / object_id | text / bigint | 对哪个对象 |
| before / after | jsonb | 变更前后；新建 before = null，停用 after = null |
| reason | text 可空 | 用户填的原因 |

action 封闭列表：price_table.create / update / deactivate；price_rule.create / update / delete / reorder；product_price.update；customer_price_table.assign；product.create / update / deactivate；customer.update；user.create / update / role / deactivate；settings.update。

- 只 INSERT：应用层无改删接口，数据库层收回 UPDATE / DELETE。
- 不记 IP、UA；不做全站日志查询页、不做登录日志；只在对应对象详情页显示「变更记录」。
- 保留永久。

## 3. 主数据

### 3.1 商品与单位

扁平 SKU：每个可售单元一条商品记录。规格是自由文本；**禁止**做属性矩阵，**禁止**做「商品 + 规格行」。

```sql
product(id, code UNIQUE, name, spec, brand_id, category_id, base_unit_id,
        ref_purchase_price numeric(12,4), standard_price numeric(12,4),
        tax_rate numeric(5,2) NOT NULL DEFAULT 13, is_integer_qty bool default false,
        barcode text null, is_active bool default true, created_at, updated_at)
product_unit(id, product_id, unit_id, rate numeric(12,4), is_base bool)   -- rate: 1 包装单位 = rate 基单位
product_alias(id, product_id, alias, pinyin)                              -- 多个别名
unit(id, name, is_active)                                                 -- 根/个/套/米/箱/件/包，可增删（停用）
category(id, name, is_active)                                             -- 一层，约 10 类
brand(id, name, is_active)
```

- 编码：自动流水号，可手工覆盖，唯一；不做扫码，barcode 留空备用。
- 每个商品一个基单位 + 0..N 个包装单位；换算率挂商品，不挂单位表；库存只按基单位记数量。
- 金额口径：入库总额为准，基单位单价 = 总额 ÷ 基单位数量，内部 6 位、展示 4 位。
- is_integer_qty = true 时，单据行数量必须是整数，0.999 直接拦，不静默取整。
- 主数据只停用、不硬删；停用后不可新选，历史可见。
- 单据行保存名称、规格、品牌、单位、换算率、单价、税率的**快照**；改主数据不影响历史单据。

### 3.2 客户与供应商

```sql
customer(id, name UNIQUE, contact, phone, address, group_id, price_table_id NOT NULL,
         payment_term_days int DEFAULT 0, credit_limit numeric(14,2),
         is_active bool DEFAULT true, created_at, updated_at)
supplier(id, name UNIQUE, contact, phone, address,
         payment_term_days int DEFAULT 0, is_active bool DEFAULT true, created_at, updated_at)
customer_group(id, name)
```

- 客户必须挂一张价格表（NOT NULL）；新建客户取 system_setting.default_price_table_id。
- 客户分组只用于筛选、批量分配价格表、信用、报表，**不参与定价**。
- 账期 payment_term_days 默认 0；到期日 = 业务日期 + 账期。
- 信用额度只提示、不拦截：开单显示「该客户已欠 X，本次后 Y」。
- **不设**「期初欠款 / 期初应付」字段——期初是流水，见 §9。
- 散客是一条真实客户档案（挂零售价表），客户字段永远必填。
- 供应商是镜像档案，不挂价格表。

### 3.3 价格表

```sql
price_table(id, name, note, is_active bool, is_builtin bool)
price_rule(id, table_id, sort_order, name, scope_type, category_id, brand_id,
           formula text, rounding_mode, decimals int, min_qty numeric(14,3) null,
           is_default bool)
price_rule_product(rule_id, product_id)
```

- 一个客户一张表；一张表可被多个客户共用；改表影响所有使用该表的客户。单客户例外先「复制为专用表」，**不叠加第二张表**。
- 表内规则按 sort_order 从上到下，先命中先用；**每张表必须有且只有一条兜底规则**（is_default = true，scope_type = all，排在最后）；表保存时校验。
- 兜底规则算不出 → **阻断**，不静默回退到标准价、别的表或历史价。
- scope_type：all / category / brand / brand_category / products；多个条件同时给时按 AND 匹配。
- 公式变量只有两个：**进价**（商品参考进价，含税、基单位）、**售价**（商品标准售价，含税、基单位）。运算只允许 + − × ÷、括号、一元负号、百分号、十进制常量；**禁止**函数、条件、跨表 / 跨客户引用、数量变量、税率变量、实际成本变量；**禁止** eval，用受限表达式解析器。
- 求值用十进制，中间保留 6 位。
- min_qty 按基单位数量比较；行单位是包装单位时先换算。

解析顺序（规范）：

1. 读客户价格表；表停用 → 阻断，提示改表。
2. 依次匹配非兜底规则：作用域 → min_qty；缺参考进价或公式结果 ≤ 0 / 非有限 → 跳过并给可见警告。
3. 命中则取 round(公式值, 规则的 rounding_mode, decimals)；行单位是包装单位时按「基单位价 × 换算率」再按同一规则舍入一次。
4. 未命中走兜底规则；兜底失败 → 阻断。
5. price_source 只能是 table_rule / table_default / manual；list_price 存解析价，unit_price 存成交价。

舍入（九步，**必须**按顺序）：

| # | 步骤 | 规则 | 位数 |
| --- | --- | --- | --- |
| 1 | 公式中间值 | 十进制，不舍入 | 6 |
| 2 | 价格表单价值 | 规则选的模式：四舍五入 / 向上 / 向下 | 0–4，默认 2 |
| 3 | 包装单位价 | 基单位价 × 换算率，同模式再舍 | 同规则 |
| 4 | 行含税金额 | round(数量 × 单位价, 2) | 2 |
| 5 | 行折后含税 | round(行含税 × 行折扣率, 2)；折扣额 = 行含税 − 折后 | 2 |
| 6 | 整单优惠分摊 | 按行折后金额比例，round(…, 2)，尾差记最后一行 | 2 |
| 7 | 未税金额 | round(折后含税 ÷ (1 + 税率), 2) | 2 |
| 8 | 税额 | 折后含税 − 未税（残差） | 2 |
| 9 | 合计 | 各行相加；价税合计 = 金额合计 + 税额合计 | 2 |

- 舍入一律 half-up；负数按绝对值舍入再加符号；不用银行家舍入。
- 逐行按单据行的税率快照算税，按税率分组汇总；不假设整单一个税率。
- 数量 × 未税单价 ≠ 未税金额的尾差属正常，以金额 / 税额为准。

### 3.4 资金账户

```sql
cash_account(id, name UNIQUE, kind, note, sort_order, is_active, created_at, updated_at)
-- kind: cash / bank / third_party / other
```

- 只能停用、不能删除；停用后不出现在新单据下拉、余额表仍列并标「已停用」。
- 不做父子账户；两张卡用名字区分。
- 类型四值只服务两件事：要不要账号信息、资金汇总怎么分组。
- 不设全局默认账户；默认 = 该账号上次使用的账户（user.last_cash_account_id），新账号落到现金账户。

### 3.5 收支项目

```sql
cash_category(id, name, direction, sort_order, is_active)   -- direction: income / expense
```

- 不分层级；用过的只能停用。
- 只服务日常收支单（P1）。

### 3.6 导入模板

五张模板：商品、客户、供应商、期初库存、期初往来；期初资金不导入（账户只有几个，手工录）。字段、匹配键、校验与批次见 §9.7–§9.8。

## 4. 单据核心（第四本账：单据流）

### 4.1 四本账

| 账 | 真相表 | 派生 | 唯一写者 |
| --- | --- | --- | --- |
| 单据流 | doc / doc_version / 各单据行表 | 状态、当前版本、打印次数 | 单据核心 |
| 库存账 | stock_movement | stock_balance（缓存兼锁点） | 库存模块 |
| 往来账 | party_entry / party_settlement | 余额与未结现算 | 往来模块 |
| 资金账 | cash_entry | 余额现算 | 资金模块 |

规则：账本表只由本模块写；单据核心在生效 / 红冲的同一事务里调用账本的过账接口，不直接写账本表。

### 4.2 骨架与主键

- 内部主键统一 bigserial；对外身份是 doc_no。
- doc：单据头，七类业务单据 + 期初 + P1 三类共用。
- doc_version：整单快照（jsonb，含明细行与结算行）、版本号、改动人、时间、备注。
- doc_line：五张货品单的货品行。
- doc_settle_line：货品单（报价单除外）的本次收付、收付款单的核销 / 退款。
- doc_cash_line：转账、日常收支、期初资金的资金行。
- doc_opening_stock_line / doc_opening_party_line：期初库存 / 期初往来行。
- doc_stocktake_line：盘点行。

### 4.3 编号

| doc_type | 前缀 | doc_type | 前缀 |
| --- | --- | --- | --- |
| sales | XS | receipt | SK |
| purchase | JH | payment | FK |
| quote | BJ | transfer | ZZ |
| sales_return | XSTH | cash_in | SR |
| purchase_return | JHTH | cash_out | ZC |
| stocktake | PD | opening | QC |

- 格式：前缀 + YYYYMMDD + 3 位当日流水，如 XS20261119001。
- **生效时取号**，同一事务内完成；草稿不占号；丢弃草稿不产生断号。
- 单号唯一、不复用、不回收；作废也不换号、不回收。
- 断号只可能来自「取号后事务回滚」，用数据库序列 / 行锁解决。

### 4.4 状态机

| 状态 | 含义 | 可做什么 |
| --- | --- | --- |
| draft | 草稿，未过账 | 编辑、自动保存、丢弃；不占号；不产生任何流水 |
| effective | 已生效，版本 vN | 打印、改单（出 vN+1）、作废；不可回到 draft |
| voided | 已作废，终态 | 查看、打印；不可改、不可恢复 |

版本是 effective 下的序列，不是第四个状态。改单 = 红冲 vN 的全部流水 + 按新内容过账 vN+1，两批都落**原业务日期**。作废 = 红冲 vN，不再重开。

### 4.5 改单 / 作废的判定

| 情形 | 判据 | 结果 |
| --- | --- | --- |
| 草稿 | 未过账 | 随便改，静默保存 |
| 有效 · 无引用 · 当月 | 核销 = 0、无退货引用、业务日期在本自然月 | 直接改，静默出 vN+1 |
| 有效 · 无引用 · 跨月 | 同上但不在本月 | 改 + 二次确认「会改写 YYYY-MM 的库存、毛利与往来」 |
| 有效 · 已核销 | 核销额 > 0 | 允许改 + 二次确认；改小超出部分退回预收 / 预付，改大增加应收 / 应付（§7.4 夹紧算法） |
| 有效 · 被退货引用 | 存在引用它的退货单 | 允许改 + 二次确认并列出引用清单；不自动改退货单，退货成本随原单重放 |
| 已作废 | 终态 | 只能查看与打印；要再用只能新建 |

- 改单默认不移动业务日期；显式改了才按新日期重放成本链。
- 删除货品行：被退货单引用时**阻断**，提示先作废退货单。
- 改行单位：**阻断**，删行重加。
- 事后补记已收的钱：**不改单，开收款单**。

### 4.6 幂等键

所有账本流水带唯一 posting key / idem_key：

- 货品行产生：`doc:{id}:v{n}:line{k}`（k = doc_line.line_no）
- 结算行产生：`doc:{id}:v{n}:settle{k}`
- 资金行产生：`doc:{id}:v{n}:cash{k}`
- 往来条目：`doc:{id}:v{n}:entry{k}`（k = 行号，单据级条目用 0）
- 红冲行：原键 + `:reversal`

同一键重复提交必须返回已有流水，不产生第二条。

### 4.10 合计区净额（硬规则）

整单优惠已按行折后金额比例分摊进每一行。因此：

- total_net / total_tax / total_gross **都是分摊后的净额**，由各行 amount_gross_final 汇总而来。
- discount_total 只是各行 discount_alloc 之和，用于印一行「优惠 X 元」，**禁止**再从合计里减第二次。
- 不做数量合计，只印「共 N 行」（根 / 个 / 箱相加是假数）。

- doc_settle_line.method（账户类型承载）。
- 单据头的收货地址、联系电话、业务员 / 经手人（票面取 created_by 的 display_name）、行仓库。
- 商品底价 / 最低售价（任何价格下限都不能由成本 × 系数推导）。
- 客户 / 供应商档案的期初欠款、期初应付。
- 应收 / 应付余额字段、收款状态字段（由核销与流水现算）。
- 资金流水的 balance_after（现算）。
- 系统设置里的 default_tax_rate（税率是商品字段）。

### 5.2 开单动线（七类业务单据的编辑器）

- **一屏**：客户、明细、合计、收款同屏；不走向导、不做两步式。
- 键盘优先：焦点顺序、快捷键、回车走完一单；目标 2–3 分钟含打印。
- 检索：编码精确 / 前缀 > 规格词 > 名称 > 别名；空格 AND；最多 8 条。命中维度相同再按「该客户买过 → 最近使用 → 销量」排序。
- 明细行内显示规格与库存数量；「上次价」进弹层，不常显。
- 生效后**直接进入打印预览**。
- 报价单与销售单共用编辑器；一键转单并锁价（§5.4）。
- 手机只读：单据列表 / 详情、库存查询、客户对账、报表；不做手机开单 / 接单 / 打印。

### 5.3 退货与换货

- 数量硬限：选了原单时，可退数量 = 原单行数量 − 已退数量；超了拦。「客户退 3 根但我只开过 2 根」走**无原单退货**（不设限，成本按 §6.4 兜底）。
- 单价默认取原单行单价，允许手工改；改价按成本链重放。
- 退货单**不设整单优惠**；想让利就改行单价。
- 退货原因可空枚举：质量问题 / 规格不符 / 客户取消 / 其他。
- 本次退款：与销售单的本次收款对称；保存时生成一张付款单（客户侧）或收款单（供应商侧），受「只能退预收 / 预付」约束。
- 换货 = 退货单 + 销售单：一次操作同屏生成，两张单互存 source_doc_id；新销售单按当前价格表解析，同品同规格可一键沿用原价；差价多退少补。**不做换货单**。
- 销售退货库存入、往来贷项；采购退货库存出、往来贷项。

### 5.4 报价单与转换

- 状态：草稿 / 有效 / 已作废；「已过期」由 valid_to 派生显示，不改状态、不跑定时任务。
- 报价单 → 销售单：沿用报价单价（锁定）；若已过期或商品现价已变，页顶提示「现价已变，差 X 元」并给「按现价重算」。
- 同一张报价单可被多张销售单引用，不消耗、不追踪已转数量；销售单行记 quote_doc_id / quote_line_no，报价单列表显示「已转 N 次」。

### 5.5 采购运费

- 采购单头：freight_amount（含税）、freight_tax_rate（默认 9%，无专票 0%）、freight_payer（supplier_advance 代垫 / collect 到付）。
- 按行含税金额比例分摊，尾差记最后一行；行上 freight_alloc / freight_alloc_net。
- 采购单价税合计仍是货款，运费单列；应付 = 货款 +（代垫 ? 运费含税 : 0）。
- 到付：生效即从 freight_account_id 付给承运人，生成一条 source_type = purchase_freight 的资金流水；不进往来、不进费用。
- 代垫：运费进本单应付，不另生成资金流水。
- 入库成本 = 货款未税 + 分摊运费未税；采购退货按原行含运费的未税单位成本回冲。

### 5.6 P1 单据

**转账单（transfer）**

- doc_cash_line 两行：role = from / to，各一个账户，amount > 0（不含手续费）；doc.fee ≥ 0。
- 过账：from 账户 −(amount + fee)，to 账户 +amount；line_role 区分方向。
- 不变量：from 合计 = to 合计；Σ 两条流水 = −fee；转出与转入不能同一账户。
- 不清往、不挂客户 / 供应商；红冲两条一起冲。

**日常收支单（cash_in / cash_out）**

- 与客户、供应商无关的收钱或花钱（房租、工资、卖废料、非采购物流费）。
- doc_cash_line 每行挂 account_id 与 category_id，amount > 0；方向由 doc_type 决定。
- 收支项目的 direction 必须与 doc_type 匹配。
- 不提供直接改余额的入口；账户对不上走「其他支出」+ 备注（如现金盘亏）。
- 采购运费**不走**本单（§5.5）。

**盘点单（stocktake）**

- doc_stocktake_line：product_id、qty_book（账面快照）、qty_counted（实盘）、qty_diff（派生 = counted − book）、unit_cost（派生）、note。
- 每条非零差异生成一条 stock_movement：source_type = stocktake。
- 盘盈按当前均价（结存 ≤ 0 时按最后进价）估值入库；盘亏按出库规则计价。
- 单独类型，不进采购 / 销售成本；报表单列盘盈 / 盘亏。
- 不产生往来 / 资金流水。

## 6. 库存账

### 6.1 stock_movement（真相）

```sql
stock_movement(
  id bigserial PK,
  product_id bigint, warehouse_id bigint,
  source_type text,          -- opening/purchase/sale/sale_return/purchase_return/stocktake/reversal/adjust
  doc_id bigint null, doc_line_id bigint null,
  posting_key text UNIQUE,
  reversal_of bigint null,
  qty numeric(14,3),         -- 带符号，入正出负；qty <> 0 OR source_type = 'adjust'
  amount numeric(16,4),      -- 未税金额，带符号
  input_tax numeric(16,4),   -- 仅采购入库 / 期初入库有值，出库为 0
  unit_cost numeric(16,6),   -- |amount / qty|
  cost_basis text,           -- actual/orig_cost/moving_avg/last_cost/reversal/manual
  biz_date date, posted_at timestamptz,
  cost_recomputed_at timestamptz null
)
```

- 索引：(product_id, warehouse_id, biz_date, posted_at, id)。
- 只追加；更正 = 反向追加一条 reversal，reversal_of 指向原行。
- 含税额 = amount + input_tax，只用于单据与应付。

### 6.2 stock_balance（派生缓存 + 并发锁点）

```sql
stock_balance(product_id, warehouse_id, qty numeric(14,3), amount numeric(16,4),
              avg_cost numeric(16,6), last_cost numeric(16,6), version bigint,
              last_movement_id bigint, last_replay_at timestamptz,
              PRIMARY KEY (product_id, warehouse_id))
```

四条不变量（夜间自检断言，不做 DB 硬约束）：

1. Σ 流水 qty = 结存 qty；Σ 流水 amount = 结存 amount。
2. qty = 0 ⇒ amount = 0。
3. avg_cost = qty ≠ 0 ? amount ÷ qty : 0。
4. 每条流水的 unit_cost = |amount ÷ qty|。

### 6.3 过账与重放

```text
post(m):
  if exists(posting_key = m.posting_key): return existing
  tx:
    b := lockBalance(product, warehouse)          // SELECT ... FOR UPDATE，缺则插零行
    if m.source_type == 'reversal':
        o := movement(m.reversal_of)
        assert m.biz_date >= o.biz_date
        m.qty = -o.qty; m.amount = -o.amount; m.unit_cost = o.unit_cost
        m.cost_basis = 'reversal'
    else if m.qty > 0:                            // 入库：金额是事实（未税）
        m.unit_cost = m.amount / m.qty
        m.cost_basis = m.cost_basis ?? 'actual'
    else:                                         // 出库：金额由结存推导
        q := -m.qty
        if b.qty > 0:
            m.amount = (q == b.qty) ? b.amount : round(b.amount / b.qty * q, 4)  // 清零法
            m.cost_basis = 'moving_avg'
        else:
            price := coalesce(b.last_cost, product.ref_purchase_price, 0)
            m.amount = round(price * q, 4)
            m.cost_basis = 'last_cost'
            warn('NEGATIVE_OUT', m)
        m.unit_cost = m.amount / q
    b.qty += m.qty; b.amount += m.amount
    b.avg_cost = b.qty == 0 ? 0 : b.amount / b.qty
    if m.qty > 0 and m.source_type in ('purchase','opening'):
        b.last_cost = m.amount / m.qty
    b.version += 1
    insert m; update b
    if exists(movement same product/warehouse with biz_date > m.biz_date):
        replay(product, warehouse)
```

```text
replay(product, warehouse):
  lockBalance(product, warehouse)
  b := {qty: 0, amount: 0, last_cost: null}
  for m in movements order by biz_date, posted_at, id:
      if m.cost_basis == 'reversal':
          new := -movement(m.reversal_of).amount
      else if m.cost_basis in ('actual','orig_cost','manual'):
          new := m.amount                          // 事实，断言不变
      else:
          new := derive(b, m.qty)                  // 与 post 的出库分支同一规则
      if new != m.amount:
          m.amount = new; m.unit_cost = new / abs(m.qty); m.cost_recomputed_at = now()
      b.qty += m.qty; b.amount += new
      if m.qty > 0 and m.source_type in ('purchase','opening'):
          b.last_cost = new / m.qty
  write b, b.last_replay_at = now()
```

- 写前锁结存行；一批单据按 product_id 排序加锁避免死锁；重放共用这把锁，天然串行。
- 夜间自检：全量重算比对，不一致报警；生成 adjust 尾差流水冲平（qty = 0、amount = −残差、cost_basis = manual、biz_date = 残差出现日）。

### 6.4 成本取值

| 场景 | cost_basis | 取值 | 重放时改写 |
| --- | --- | --- | --- |
| 采购入库 | actual | 单据未税金额（含分摊运费） | 否 |
| 期初入库 | actual | 期初单未税金额 | 否 |
| 销售出库 | moving_avg | 当时结存均价；清零法 | 是 |
| 红冲 | reversal | 原流水相反数 | 跟随原行 |
| 销售退货（有原单） | orig_cost | 原行 unit_cost | 否 |
| 销售退货（无原单） | moving_avg | 当前均价；结存 ≤ 0 取最后进价 | 是 |
| 采购退货 | orig_cost | 原入库 unit_cost（含分摊运费） | 否 |
| 负库存出库 | last_cost | 最后进价 → 参考进价 → 0 | 是 |
| 盘盈 | moving_avg | 当前均价；结存 ≤ 0 取最后进价 | 是 |
| 盘亏 | moving_avg | 出库规则 | 是 |
| 手工调整 | manual | 人工指定 | 否 |

- 采购入库遇负结存，不追溯已发生的出库成本（进货是正向流水，不触发重放）。
- 零成本出库：最后进价与参考进价都为空 / 0 时，单据上标「零成本出库」。

### 6.5 负库存

- 允许，不阻断；数量、金额、均价都可以为负，报表如实显示，不做 0 下限。
- 告警两处：首页角标「负库存 N 个商品」；库存查询的负库存清单（商品、数量、金额、最后一次出库单）。
- 金额允许为负是账面事实；不提供直接改结存的入口。

### 6.6 精度与尾差

- 库存只按基单位记；数量 3 位小数、金额内部 4 位（展示 2 位）、单价内部 6 位（展示 4 位）。
- 整数量商品：单据行数量必须整数；库存流水按 qty_base 校验整数。
- 清零法：出库数量恰好等于结存数量时，金额取结存金额全额，保证「数量归零则金额归零」。
- 重放后仍出现 qty = 0 而 amount ≠ 0：生成 adjust 尾差流水冲平，不改历史出库数字。

### 6.7 库存不变量

1. 任一商品：Σ stock_movement.qty = stock_balance.qty；Σ amount = stock_balance.amount。
2. qty = 0 ⇒ amount = 0。
3. 任一单据版本的全部库存流水净额 = 用该版本内容独立过账的净额；作废单为 0。
4. 红冲行金额 = −原行金额；红冲行 biz_date ≥ 原行 biz_date。
5. 期初流水 cost_basis = actual，永不重算；未红冲期初流水每商品至多一条。
6. 同一 posting_key 只产生一条流水。

### 7.2 party_settlement（核销分配）

```sql

  id bigserial PK,
  clear_entry_id bigint, open_entry_id bigint,
  party_id bigint,
```

| 事件 | 类 | 方向（amount） | 备注 |

| 采购退货 | clear | − | 镜像 |
| 收款单 | clear | −（现金 + 折让） | 自动分配 |
| 收款退款 | clear | + 现金 | ≤ 当前预收 |
| 付款单 | clear | −（现金 + 折让） | 镜像 |
| 付款退款 | clear | + 现金 | ≤ 当前预付 |

### 7.4 夹紧（改单、作废、红冲的统一处理）

```text
onAmountChanged(doc):
  newAmount = 该单据当前净额
  allocated = 它的有效分配之和
  if allocated > newAmount:
    excess = allocated - newAmount
    从最近一次分配开始，逐条追加反向分配行，直到 allocated == newAmount
```

- 挂账单改小 / 作废：超出部分退回对应清账单的可用池。
- 清账单红冲（收款单作废）：它的分配全部释放，被它结掉的单据回到未结。
- 释放顺序：分配时间从晚到早。
- 二次确认文案写明退回金额。
- 票 3 的三条搬运规则（改小转预收、改大加应收、作废已核销全额转预收）是这个算法的特例，不另写代码。

### 7.5 收款单 / 付款单

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 客户 / 供应商 | ✓ | 一张单只对一个对象 |
| 类型 | ✓ | 收款 / 退款（付款镜像） |
| 业务日期 | ✓ | 默认今天 |
| 资金账户 | ✓ | 收款与退款都记 |
| 现金金额 | ✓ | ≥ 0 |
| 折让金额 | | ≥ 0；退款类型不填 |
| 折让原因 | 折让 > 0 时 | 抹零 / 让价 / 坏账 / 其他 |
| 核销明细 | 自动生成 | 每行 = 单据 + 金额；可改、可撤销 |

- 现金 + 折让 = 本次清账金额；资金侧只认现金。
- 允许「现金 0 + 折让全额」= 坏账核销 / 减免。
- 自动分配顺序：到期日从早到晚，同到期日按业务日期、再按单号；分配总额 ≤ 未结合计，超出即预收。
- 退款类型：金额记正、不做折让；校验 ≤ 当前可用（预收 / 预付）。
- 红冲收款单 = 追加反向清账流水 + 释放全部分配。

### 7.6 对账单

`text
getStatement({ party, from, to }) → {
  header:   { partyName, from, to, openingBalance, closingBalance,
              lastReconciledAt, repostedAt },
  movements:[{ bizDate, type, docNo, summary, amount, balanceAfter }],
  openDocs: [{ bizDate, docNo, amount, settled, open, dueDate, overdueDays }],
  totals:   { openTotal, creditTotal, closingBalance }
}
`

- 期初余额 = biz_date < from 的全部流水之和；标签「期初余额（截至 {from−1}）」；不存上期结转。
- 发生额 = [from, to] 的流水，按（biz_date, posted_at, id）排序，逐行累计 balanceAfter。
- 未结清单据 = 截至 to 的挂账单：amount(to) − settled(to) > 0；settled 只计 effective_date ≤ to 的分配；按业务日期升序。
- 不变量：openTotal − creditTotal = closingBalance；closingBalance = openingBalance + Σ movements。
- 时点口径：只看截至 to 已发生的流水与已生效分配；之后收到的钱不回头改写历史账单。
- 默认期间：from = 上次对账记录 period_to + 1 天；无记录则早于第一笔流水；to = 今天。可改任意区间。
- 粒度：单据级；v1 不做商品明细展开。
- 表头：客户名、期间、期初 / 期末、上次对账日、最近更正时间（期间内有红冲时提示）。

### 7.7 账龄

- 只算挂账单：open > 0 的销售单、采购单、期初应收 / 应付。
- 到期日 = 业务日期 + 账期；逾期天数 = asOf − 到期日；asOf = 到期日当天算未到期。
- 六桶：未到期（≤ 0）/ 1–30 / 31–60 / 61–90 / 91–180 / >180。
- 部分核销：剩余未结金额**整笔**落在该单到期日所在桶，不拆行。
- 退货贷项、预收 / 预付不进桶，单独列「可用抵扣」「预收 / 预付」。
- 各桶合计 = 未结合计（截至 asOf）。

### 7.8 statement_record（对账记录）

```sql
statement_record(id, party_type, party_id, period_from, period_to,
                 closing_balance, open_total, credit_total,
                 operator_id, created_at, note)
```

- 只记事实：不写流水、不回写单据状态、不冻结数字。
- 「上次对账日」= 最近一条记录的 period_to；对账单默认期间与改单提示从这里取。
- 允许补录历史对账，日期可改。

### 7.9 往来不变量

1. 任一对象：余额 = Σ party_entry.amount。
2. 余额 = 挂账未结合计 − 清账可用合计。
3. 任一挂账单：0 ≤ 已核销 ≤ 当前挂账额；未结 = 当前挂账额 − 已核销。
4. 任一清账单：0 ≤ 已核销 ≤ 清账额；可用 = 清账额 − 已核销。
5. 单据当前挂账额 = 最新版本金额；历史版本流水净额为零。
6. 退款金额 ≤ 当前可用（预收 / 预付）。
7. 对账单：期末 = 期初 + Σ 发生额；未结合计 − 可用合计 = 期末。
8. 账龄：各桶合计 = 未结合计。
9. 资金侧：收款单现金合计 = 该单生成的资金流水合计（方向相反）。

### 8.1 cash_entry（真相）

```sql
cash_entry(
  id bigserial PK,
  account_id bigint,
  biz_date date,
  amount numeric(14,2),      -- 带符号，正入负出，不为 0
  source_type text,          -- receipt/payment/transfer/cash_in/cash_out/purchase_freight/opening
  source_doc_id bigint, source_doc_version int, source_line_id bigint,
  line_role text null,       -- transfer 的 from / to
  party_id bigint null,
  counter_account_id bigint null,
```

- 只追加；更正 = 追加 reversal_of 反向流水。
- 不存 balance_after；余额按（biz_date, posted_at, id）现算。
- 索引：(account_id, biz_date, posted_at, id)、(source_doc_id, source_doc_version)。

### 8.2 来源与记账规则

| 事件 | source_type | 条数 | 金额 |
| --- | --- | --- | --- |
| 收款单 vN 生效 | receipt | 每条 amount ≠ 0 的结算行 1 条 | +amount |
| 付款单 vN 生效 | payment | 同上 | −amount |
| 转账单 vN 生效 | transfer | 2 | 转出 −(金额 + fee)、转入 +金额 |
| 日常收支单 vN 生效 | cash_in / cash_out | 1 | ±金额 |
| 采购运费（到付） | purchase_freight | 1 | −运费含税 |
| 期初单 vN 生效 | opening | 每账户行 1 条 | 行金额（可负） |
| 改单 | 同上 | 先红冲 vN 全部，再按 vN+1 生成 | 两批都落原业务日期 |
| 作废 | 同上 | 红冲 vN 全部 | 不重开 |
| 折让 / 整单优惠 / 折扣 | — | 0 | 只改往来与票面 |

- 资金流水 = 收付款单每条结算行的现金部分，1:1；折让只改往来、不改资金。
- 退款是业务单据（收付款单的退款类型），不是红冲。
- 幂等键见 §4.6；红冲行加 :reversal。

### 8.3 转账单（P1）

- doc_cash_line 两行：role = from / to，account_id、amount（正数）。
- doc.fee = 手续费 ≥ 0；流水：from −(amount + fee)，to +amount。
- 不变量：from 合计 = to 合计；Σ 两条流水 = −fee；两账户不同。
- 不清往、不挂客户 / 供应商；红冲两条一起冲。

### 8.4 日常收支单（P1）

- doc_cash_line 每行：account_id、category_id、amount > 0；方向由 doc_type 决定。
- 一条流水，账户必填；没有挂账形态。
- 收支项目 direction 必须匹配。
- 不提供直接改余额的入口。

### 8.5 期初资金

见 §9.4：每账户一行，source_type = opening，业务日期 = 该账户启用日前一日；每账户至多一条生效期初。

### 8.6 查询契约

`text
getAccountBalances({ from, to }) → [{ accountId, name, kind, opening, inflow, outflow, closing }]
getAccountJournal({ accountId, from, to, sourceType? }) →
  [{ bizDate, docType, docNo, summary, partyName, counterAccountName,
     inflow, outflow, balanceAfter, isReversal }]
`

- opening = Σ amount where biz_date < from（含期初流水）
- inflow = Σ amount > 0；outflow = Σ |amount < 0|；closing = opening + inflow − outflow
- balanceAfter 按（biz_date, posted_at, id）窗口累计现算
- 已停用账户照常出数并标「已停用」；红冲行显示为负数并标「红冲」

### 8.7 资金不变量

1. 任一账户：closing = opening + inflow − outflow = Σ cash_entry.amount。
2. 任一收付款单版本：结算行现金合计 = 该版本资金流水之和；收款为正、付款为负；折让不计。
3. 任一转账单：Σ 两条流水 = −fee；转出金额 = 转入金额。
4. 任一日常收支单：恰好 1 条流水，金额 = 单据金额。
5. 任一单据：全部版本流水净额 = 当前生效版本应产生的净额；作废单为 0。
6. 每账户至多 1 条未红冲期初流水；业务日期 = 启用日前一日。
7. 资金流水无 UPDATE / DELETE：应用层无接口，数据库收回权限。
8. 折让不产生资金流水。
9. 停用账户不能出现在新单据上；旧单据改单不受影响。
10. 业务日期早于启用日的业务单据不得生效（草稿除外）。
11. 全局：Σ 所有账户余额 = Σ 所有资金流水。

## 9. 期初与导入

### 9.1 三类期初单

doc_type = opening，opening_kind ∈ stock / party / cash；共用骨架、版本链、红冲、作废、权限（仅管理员）。

| | 期初库存单 | 期初往来单 | 期初资金单 |
| --- | --- | --- | --- |
| 粒度 | 一张；可多张并存 | 一往来对象一张 | 一张；后加账户另开一张 |
| 单据业务日期 | 启用日前一日 | 默认启用日前一日，只作录入归属 | 启用日前一日 |
| 流水日期 | = 单据业务日期 | = 行上的原发生日期（全系统唯一例外） | = 单据业务日期 |
| 行表 | doc_opening_stock_line | doc_opening_party_line | doc_cash_line |
| 落账 | stock_movement(opening) | party_entry(open/clear) | cash_entry(opening) |

### 9.2 期初库存

- 一行一个商品；单仓；qty ≠ 0，整数量商品必须整数。
- unit_cost 必填，默认参考进价；不允许留空；填 0 必须显式勾「零成本期初」，单据与行都标。
- amount = round(qty × unit_cost, 4)，只读。
- 落账：source_type = opening、cost_basis = actual、永不重算；是成本链的起点。
- 期初库存按**未税**录入，不记进项税。

### 9.3 期初往来

- 一对象一张单；行：direction（应收 / 应付 / 预收 / 预付）、origin_doc_no（可空）、origin_date（必填）、amount > 0、note。
- 应收 / 应付 → party_entry.open；预收 / 预付 → party_entry.clear。
- **party_entry.biz_date = origin_date**，不是单据日期。
- 到期日 = origin_date + 账期；可被后续收付款核销，进未结清单、进账龄。
- 不产生销售统计与毛利；改期初按 §7.4 夹紧自动释放多出的分配。

### 9.4 期初资金

- 每账户一行，source_type = opening，业务日期 = 该账户启用日前一日；金额可负。
- 每账户至多一条生效期初；后加账户另开一张只含该账户的期初单。
- 期初资金不导入，手工录。

### 9.5 启用日

- 启用日 = min(生效期初单.biz_date) + 1。
- 任何期初单业务日期 ≤ 当前最早生效业务单据业务日期 − 1，否则拒绝生效（草稿可存）；没有业务单据时不设限。
- 业务单据（七类 + P1）业务日期早于启用日 → 生效拦截、草稿可存。
- 启用日不是系统参数，没有「改开账日期」动作；只能改期初单日期（走版本链）。
- 每商品 / 每往来对象 / 每资金账户至多一条未红冲期初流水；多张期初单可并存，但不得重复覆盖同一对象。

### 9.6 更正

- 期初单就是普通单据：改单 = 红冲 vN 全部流水 + 按新内容过账 vN+1；两批都落各自原日期。
- 不设日历冻结、不加审核；闸门沿用 §4.5（下游引用 + 二次确认）。
- 库存期初改动触发成本链重放，二次确认写明「会重算 YYYY-MM 起的成本」，报表标最近重放时间。
- 权限：期初单的新建、改单、作废与导入只对管理员开放。
- 作废是终态；再录只能新开一张。

| 供应商 | 名称 | 名称 | 主数据 upsert |
| 期初库存 | 商品编码、数量 | 商品编码 | 期初整批 |
| 期初往来 | 对象类型、对象名称、方向、原发生日期、金额 | 对象名称分组 | 期初整批 |

- 主数据：逐行 upsert、部分成功、逐行错误报告；编码为空视为新建。
- 期初：整批，一行不合法则整批不写；分批导入 = 多张期初单。
- 两种通道都**先干跑**：零写入，逐行报「行号 + 列 + 原文 + 原因 + 修正建议」，可下载；确认后才执行。
- 期初导入前查重：该商品 / 对象已有未红冲期初 → 拦。
- 校验：金额 2 位、数量 3 位；整数量商品的期初数量必须整数；期初数量 ≠ 0；客户 / 供应商名称文件内唯一；对象必须存在且未停用；方向与对象类型匹配；金额 > 0；同一对象同一原单号不得重复；单位 / 分类 / 品牌 / 分组 / 价格表名不存在 → 报错，不自动建档，给缺失清单。
- 导入顺序提示：商品 → 客户 / 供应商 → 期初。
- 格式：xlsx 为主，csv 兼容；模板自带字段说明、示例行、枚举列下拉；别名用英文逗号分隔。

### 9.8 导入批次

```sql
import_batch(id, kind, file_name, file_hash, row_total, row_ok, row_failed,
             error_report jsonb, doc_ids jsonb, state, operator_id, created_at)
-- state: dry_run / committed / reverted
```

- 期初批次撤销 = 红冲 doc_ids 里的期初单（整批）。
- 主数据批次撤销 = 批量停用本批次新增的项（不做字段回滚）。
- 幂等：同一文件哈希 + 同一对象重复上传 → 期初拦截、主数据提示「这份文件已导过」。

### 9.9 期初不变量

1. 每商品 / 往来对象 / 资金账户至多一条未红冲期初流水。
2. 期初库存行 amount = round(qty × unit_cost, 4)；qty ≠ 0；整数量商品为整数。
3. 期初库存 cost_basis = actual，永不重算；Σ 未红冲期初库存流水 = 启用日零点结存。
4. 期初往来：Σ open − Σ clear = 该对象在启用日的往来余额；行 biz_date = origin_date。
5. 期初不产生销售 / 采购统计与毛利。
6. 期初资金每账户至多一条；业务日期 = 该账户启用日前一日。
7. 启用日定义与日期约束（§9.5）。
8. 期初单改单后：全部版本流水净额 = 当前版本应产生的净额。
9. 导入批次与 doc_ids 一一对应；撤销后该批次期初事件净额为零。
10. 干跑零写入。

## 10. 报表

### 10.1 公共口径

- 四张表没有自己的数据，全部从三本账现算；不建汇总表、不缓存、不异步。
- 时间只有业务日期一条轴；默认本月，可选日 / 月 / 年 / 自定义。
- 金额主口径未税；税额 = 含税 − 未税（残差），按单据行税率快照算。
- 折扣三层已净：行折扣、整单优惠分摊、让价；收入直接用行净额。
- 收款折让只改往来，不进销售统计与毛利。
- 成本类金额按 can_view_cost 整列过滤；导出同过滤。
- 页眉：「数据截至 YYYY-MM-DD HH:mm」+「最近一次成本重放：YYYY-MM-DD HH:mm」；本期间有红冲时页脚提示「本期间数据于 YYYY-MM-DD 更正过」。
- 负库存商品的成本是估价：行上标「含估价成本」，页脚给负库存商品数。

### 10.2 销售统计

视图：按日 / 月、按商品、按客户（可切分组）、单据明细。

| 列 | 定义 |
| --- | --- |
| 期间 | 业务日期归期 |
| 单据数 | 生效销售单 + 退货单 |
| 数量 | Σ 基单位数量，退货为负 |
| 未税销售额 | Σ 行未税净额 |
| 销项税额 | Σ 行税额 |
| 价税合计 | 未税销售额 + 销项税额 |
| 退货额 / 退货率 | 退货单未税额（正数单列）/ 退货额 ÷ 销售单未税额 |
| 让价额 | Σ（解析价 − 成交价）× 数量，含税，只作价格纪律参考 |
| 未税销售成本 | Σ 出库未税成本；退货按原单成本回补为负 |
| 毛利 / 毛利率 | 未税销售额 − 未税销售成本；毛利 ÷ 未税销售额 |

- 草稿、作废、报价单不算；改单按版本净额；退货按自己的业务日期；收款折让不进。

### 10.3 进货统计

视图：按日 / 月、按供应商、按商品、单据明细。

| 列 | 定义 |
| --- | --- |
| 单据数 | 生效采购单 + 采购退货单 |
| 数量 | Σ 基单位数量，退货为负 |
| 货款未税 / 进项税 / 货款价税合计 | 行净额 |
| 运费（含税）/ 运费未税 | 单据头运费 / round(运费含税 ÷ (1+税率), 2) |
| 入库成本 | 货款未税 + 运费未税 |
| 退货额 / 退货率 | 按原入库行单位成本（含分摊运费）/ 退货额 ÷ 采购单入库成本 |
| 净入库成本 | 入库成本 − 退货额 |

- 应付余额不进本表（归对账单与账龄）。

### 10.4 库存统计

- **现时结存**：商品编码 / 名称 / 规格 / 品牌 / 基单位 / 数量 / 未税均价 / 未税结存金额 / 最后入库日 / 最后出库日 / 负库存标记 / 呆滞标记。均价 = 结存金额 ÷ 结存数量，数量 0 则金额 0。店员只见数量列。
- **进销存汇总（商品 × 期间）**：期初数量 / 金额、采购入库、采购退货、销售出库、销售退货、盘盈、盘亏、调整、期末数量 / 金额。期初 = 期间首日之前全部流水之和；每行必须满足「期初 + 入 − 出 = 期末」，数量与金额各算一次。
- **商品流水明细**：业务日期、来源类型、来源单号、数量、未税金额、未税单价、成本来源、是否被重放改写过。
- **呆滞清单**：90 / 180 天无出库且结存 > 0，按未税结存金额降序，显示最后出库日与呆滞天数。**不做库龄**。
- **期初**：期初库存按未税金额录入；报表不存上期结转。

### 10.5 资金统计

- **账户余额表**：账户 / 类型 / 期初余额 / 本期收入 / 本期支出 / 转账净额 / 期末余额；现算。
- **账户收支明细**：业务日期 / 账户 / 来源类型 / 来源单号 / 对手 / 摘要 / 金额（带符号）/ 逐笔余额。
- **按来源类型汇总**：八类——销售收款、采购付款、销售退款、采购退款、采购运费、日常收支、转账、期初资金；列笔数与金额净额；转账单列一行、净额 0。
- v1 不按收支项目分组（P1 上线后自动带出）。
- 资金统计不含成本与毛利，店员可见。

### 10.6 导出与打印

- 打印：浏览器直接打印报表页；@page A4，明细类横向、结存类纵向；隐藏筛选条，页脚印期间、数据截至、重放时间、页码；不走单据模板引擎、不走针式。
- 导出：服务端生成 .xlsx 单 sheet，文件名「报表名_起始日_结束日.xlsx」；表头带期间与数据截至；成本列按看成本过滤。
- 页面与导出调用同一查询函数。

### 11.5 针式几何

- @page size: 241mm 93mm; margin: 0；页面盒 241×93mm，内容宽 210mm，左边留 2–3mm，高度留 0.1–0.2mm 余量。
- 每页固定 6 行，最多 3 页（18 行）；超过提示改用 A4，不自动混纸。
- 每页重复店铺头 / 客户 / 单号 / 页码「第 x/y 页」；合计只印最后一页；每页一个固定 .sheet（相对定位 + 绝对定位字段）。
- A4 流式分页：thead 每页重复，行 break-inside: avoid。
- 首次使用做一次校准（每台电脑 + 每台打印机，管理员）：校准页（角标 + 10mm 网格），量偏移，调打印机；软件 x/y 偏移只做微调，存本机。
- 打印页常驻检查：模板纸型 = 驱动纸型 = 实际纸；页边距默认；缩放 100%。
- 预览不读驱动纸型，预览 ≠ 实打，是已知差异。

### 11.6 时点、版本与留痕

- 可打印：有效、已作废；草稿只能屏幕预览。
- 版本 ≥ 2 右上印「第 N 版」；旧版本印「已被第 N 版取代」灰底横幅；作废单印斜向「作废」水印。
- 页脚每次印打印时间；第 2 次起加「补打」。print_count / last_printed_at / 操作人入库；预览不计数；不设打印次数上限。
- 重打同版本：除打印时间 / 补打标记外内容一致。
- v1 不存 PDF；需要时按快照重新渲染，或用浏览器另存 PDF。
- 打印件不出现成本字段，也不印实时客户累计应收；余额只在对账单上按截止日呈现。

- 任何写操作都要有成功 / 失败反馈；失败必须说明原因，不只说「保存失败」。
