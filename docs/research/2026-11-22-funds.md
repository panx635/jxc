## 结论摘要

1. **账户类型枚举最多两个值**：精斗云明文「系统预置现金和银行存款两类,暂不支持新增或是修改」；好生意按「账号类型」区分、银行账号才要开户行与账号；星辰的账户档案**根本没有类型字段**——微信、支付宝就是一个叫「微信」的账户。把「微信 / 支付宝」做成枚举的只有秦丝（预置 6 个账户），而且它的「账户类型」字段官方明说「目前系统业务中并没有用到此标识」。
2. **没有一家把可编辑的「结存余额」放在账户档案上**：档案上只存「期初余额 + 余额日期」（精斗云、好生意、T+、星辰、管家婆都是这条路线），当期余额由期初 + 流水汇总出来；星辰还提供「余额重算」「同步出纳余额」按钮，T+ 的余额落在 CS_CashAccount 这种可重算的表里。
3. **同一家会并存两套余额口径**：星辰「账户余额表」（业务单据口径）与「出纳余额表」（日记账口径）分开，官方明说对不上时要查期初是否同步、单据是否都生成日记账；T+「最新余额」含未审核日记账、「实际余额」只含生效数据。这是双账套（进销存 + 出纳分开启用）的必然代价。
4. **转账单是行业标配，但手续费挂哪侧各家不同**：星辰有独立的「资金转账单」，手续费是**转出侧**字段「转出手续费」，且明文「资金转账单中不支持录入转入账户手续费」；好生意「银行存取款单」用「手续费/差异」一个字段按两金额差额算，可正可负；网上管家婆「提现/存现/转账」把手续费并进付款额，「实际付款金额=收款账户金额+手续费」；T+ 的「银行存取款单」只有「差异」没有手续费。
5. **转账必须产生两条流水**：好生意「单据生效后才写入现金银行流水，记录两条信息，一条是转入账号信息，一条是转出账号信息」；T+ 要「在两个账号里面都引入一次」；星辰一张转账单同时动转出、转入两个账户。
6. **纠错一律不允许直接改已生效的收付款单**：好生意列出 6 条前置（弃审、删凭证、反锁账、删收付款单、清核销、非自动生成）；星辰转账单删除要过「未结账 / 已反审核 / 未生成凭证 / 未生成日记账」四关；管家婆「已经过账的单据不能操作反审核」，只能「红冲单据」后重做。**允许直接改删资金流水的只有秦丝**（「资金流水账内操作列可选择删除或修改某一条流水」），这是反面样本。
7. **资金侧金额与往来侧核销金额天然不等，差额必须有归属**：星辰用「优惠金额」承接（官方例：核销 38、收款 30、优惠 8）；T+ 用「表头手续费 + 冲抵应收」承接（应收 1130、实收 1128，差额自动生成一张应收方向的费用单）；好生意用「现金折扣」承接并分摊到核销明细；网上管家婆用「优惠」（结算 2560、实付 2500）。
8. **退款在资金侧是反向业务、独立单据，不是红冲**：星辰资金管理预置「收款退款 / 预收退款 / 付款退款 / 预付退款 / 其他收入退款 / 其他支出退款」六种退款单；好生意付款单单据类型包含「付款单和退款单」。星辰「账户余额表」的取数说明还规定：销售退货同单退款、其他应收（收入）退款、预收退款「合计在支出总额中」。
9. **期初的载体只有三种，且都绑「启用期间」**：账户档案上的期初余额字段（精斗云、星辰账户初始数据）、独立期初录入界面（好生意「现金银行期初」、T+「现金银行期初余额」）、期初调整流水（秦丝「账户期初调整」）。代价是期初改不动：精斗云「期初余额只能在启用期间补录,若已结账需反结账到启用期间再操作」，T+ 出纳与现金往来启用期间必须相同才能录期初。
10. **负余额以「提示」为主，硬拦只出现在收付款动作上**：精斗云「赤字检查」明说「仅是录凭证时提醒作用,点击【确定】按钮后,仍可以继续保存凭证」；T+ 有赤字控制，做付款单时会「提示账户资金不足」，但日记账上账户余额可以是 -2；秦丝直接允许负余额（官方截图里「默认账户 -26.00」）。
11. **「资金日报」这个词不能乱用**：星辰手机端有个「收支日结」，官方定义是「只显示未生成日记账的单据」——那是待办清单，不是余额日报；真正的日报口径要么是账户余额表的日切，要么是账户收支明细表按日汇总。
12. **报表口径可以归纳为四张**：账户余额表（期初 + Σ收 − Σ支，含未生成日记账的业务单据）、资金流水账（逐笔，按单据时间倒序）、资金日报（日切快照）、现金流（流入 / 流出 / 净流入，星辰资金分析的定义是「净流入 流入金额-流出金额」）。

## 1. 账户档案：字段与账户类型（R1）

### 事实

1. **星辰的账户档案字段是「编码 + 名称 + 银行信息 + 币别 + 默认」，没有类型字段。** 官方操作指南写：「单击【新增】按钮，在弹出的【账户管理】窗口，录入账户编码、账户名称、银行账号、开户名、开户行、备注，选择币别，设置是否默认账号，再单击【保存】即可完成账户录入返回主界面。」同一页还有「如果需要对已增加的账户管理进行删除、禁用等操作」与「账户管理新增时，不允许编码一致，名称可以一致」。（金蝶云星辰《账户管理》，https://vip.kingdee.com/knowledge/484731308120232704?productLineId=35&isKnowledge=2&lang=zh-CN ；《如何新增和管理企业资金账户?》，https://vip.kingdee.com/knowledge/391351996323520000?productLineId=35&isKnowledge=2&lang=zh-CN）
2. **星辰账户是平级档案，不能建父子账户，可以 Excel 引入。** 「各账户之间是平行的关系,不能新增上下级账户。」「如果账户信息过多也可以在excel表格里面填好再导入」。（金蝶云星辰《如何新增和管理企业资金账户?》，https://vip.kingdee.com/knowledge/391351996323520000?productLineId=35&isKnowledge=2&lang=zh-CN）
3. **精斗云的账户类型是两值固定枚举。** 「账户类别:系统预置现金和银行存款两类,暂不支持新增或是修改。」「账户层级:账户都是平级的关系,不支持设置下级账户(即子账户)。同一银行有多个账户,建议可通过命名区分(如 “农业银行 01”“农业银行 02”)。」「账户编号和账户名称:为必录项,不能为空。」（金蝶精斗云《账户(结算账户)怎么新增?期初余额怎么录?》，https://vip.kingdee.com/knowledge/12239?productLineId=6&isKnowledge=2&lang=zh-CN）
4. **精斗云账户只能手工建，不能导入导出。** 「操作:账户信息与期初余额仅支持手工新增,暂不支持批量导入/导出功能。」（同上）
5. **T+ 的账户叫「账号」，在「基础设置」下，带账号类别与银行对账开关。** 出纳实操页反复出现「账号类别：现金 / 账号名称：现金 / 账号：现金 / 开户银行：」这一组字段；银行对账页明确「（1）需要进行银行对账的账号需要勾上“银行对账”；」。（畅捷通 T+《T+12.2银行对账》，https://service.moni.chanjet.com/doc/cate-68/doc-4901.html ；《T+银行存取款单怎么引入出纳》，https://service.moni.chanjet.com/doc/cate-68/doc-35354.html）
6. **好生意把「账号」和「结算方式」做成两张档案，并在结算方式上挂默认账号。** 「新增账号 账号类型为银行时，需要录入开户银行及账号」「2、新增结算方式：录入结算方式编码、名称，选择默认账号即可」。（畅捷通好生意《好生意标准版操作手册》「三、基础信息 / 3、收付信息 / 1）结算方式、账号」，https://service.moni.chanjet.com/doc/cate-24/doc-35610.html）
7. **秦丝的账户字段最全，但「账户类型」是装饰字段。** 「名称* / 账号 / 开户人 / 门店 / 账户类型 / 排序 / 启用 / 备注」；同时写明「账户类型：为账户选择一个类型，做类型标识，可不选择，目前系统业务中并没有用到此标识。」「排序: 设置一个整数的值，用于在列表中展示排序依据，值越小越靠前。」系统预置账户是「现金 / 微信记账 / 支付宝记账 / 秦丝支付 / 余额支付 / 刷卡」，另有「默认账户」。（秦丝《结算账户管理（收款方式、交易银行卡等）》，https://qinsilk.com/mms/front/help/gis/help-id1226.html）
8. **秦丝的账户有门店归属，且用过不能删只能停用。** 「门店：选择一个门店，注意选择门店后该账号只能在所属的门店中使用。」「（注：使用过的结算账户不支持删除，如果后续不在使用该账户可以设置为停用）。」（同上）
9. **网上管家婆的账户是「一个名字」，与真实银行账户无绑定。** 「用于创建各类账户名，与真实账户无直接关联。如中国银行账户，支付宝账户，财付通账户等。」（网上管家婆《● 现金银行》，https://help.wsgjp.com/5e03/440d/c19c/5d2e/ca7f）
10. **舟谱的账户档案可选「自动创建会计科目」。** 「档案管理-账户管理中创建账户即可，如有财务需求，需要勾选自动创建会计科目。」（舟谱《如何添加收款账户？》，http://wk-pro.zhoupudata.com/help/143）

### 对 jxc 的含义

- **账户类型只留「现金 / 银行存款」两值就够，微信、支付宝做成账户名。** 星辰干脆没有类型字段，精斗云只有两值且不许改，两者都已经覆盖 1–3 人店的需求；把微信、支付宝做成枚举（秦丝路线）会立刻遇到「微信收款到的是绑定的银行卡」这种归属问题，还要多一层「类型 → 科目」映射。jxc 采用两值枚举：cash / bank，微信、支付宝都是 bank 下的账户名。
- **账户档案要带「停用」和「默认」两个开关，不要做「删除」。** 星辰有禁用、秦丝有启用状态且用过不能删——这不是洁癖，是因为资金流水是不可变流水，账户一旦有流水就不能物理删除，否则历史流水的账户外键会悬空。这正好和 jxc 的账本模型一致：账户只能停用，流水里存 account_id 快照 + 名称快照。
- **不要做账户层级（父子账户）。** 星辰、精斗云都明文不支持，理由是余额要能一眼看全；树的代价是每张报表都要「含下级」开关与合并口径。需要区分「同一家银行的两个卡」时用命名（精斗云的建议就是「农业银行 01/02」）。
- **排序字段和门店归属是门店版才需要的。** 秦丝有门店绑定与排序，是因为它服务连锁零售；jxc 单店，v1 不做门店维度，排序留给前端拖拽即可，不必建字段。

## 2. 账户余额口径：派生还是存储（R2）

### 事实

1. **星辰没有「账户结存」字段，余额是报表从「账户初始 + 业务单据」汇总出来的。** 「账户余额表:用于查询进销存及资金收付款单对应的账户收支合计与余额。数据来源于账户初始及进销存业务单据上的账户收支。」（金蝶云星辰《账户余额表与出纳余额表如何使用?》，https://vip.kingdee.com/knowledge/560991667763602688?productLineId=35&isKnowledge=2&lang=zh-CN）
2. **星辰同时存在第二本账「出纳余额表」，取数源不同。** 「出纳余额表:可查询出纳管理中所有账户的发生额和余额情况。数据来源于账户初始及日记账上的收支。」（同上）
3. **两本账会对不上，官方给了排查清单。** 「若账户余额表与出纳余额表对不上,需检查期初是否同步一致,所有资金单据是否都生成了日记账,并且所有日记账是否都在资金单据里面体现。」（同上）
4. **星辰的余额可以重算、可以从出纳同步。** 「报表提供【同步出纳余额】功能,主要应用于财务先启用并录入了出纳数据,业务后启用时,可以通过此功能,将业务启用期间对应的出纳余额同步到进销存中。」「报表提供【余额重算】功能,点击后可以按查询条件,重新计算账户余额表数据。」（同上）

### 对 jxc 的含义

- **余额绝不要做成账户档案上的可编辑字段。** 七家里没有一家这么做：期初在档案上，余额靠汇总，连「余额重算」这种按钮都留着，就是在承认余额是缓存。jxc 已有「不可变流水 + 派生结存」，资金账户照抄这个模型即可：余额 = 期初 + Σ(带符号流水)，期初单独一张带日期的记录，余额现算或按日物化。
- **星辰的双账本（账户余额表 / 出纳余额表）是代价换来的能力，jxc 不应该抄。** 它换来的是「财务先启用出纳、业务后启用」的迁移自由；代价是两个余额长期不一致，官方只能给排查清单（期初是否同步、单据是否都生成日记账）。1–3 人店只有一个操作者，一套流水一套余额就够；如果以后要接出纳/银行对账，再加「日记账」这一层，不要让两本账并存。
- **T+ 的「最新余额 / 实际余额」双口径值得借一个概念、不值得借两个字段。** 值得借的是「未生效的流水要不要计入余额」这个问题必须显式回答；不值得借的是在报表上同时给两个数——小店会被「到底哪个是钱」问死。jxc v1：只把生效流水计入余额，草稿单在单据列表里提示，不进余额。
- **余额重算要有，但只作为运维手段。** 星辰的「余额重算」、T+ 的脚本重算都是兜底；jxc 若把余额物化成表，必须同时提供「按流水重算」的校验命令，并在报表上显示「期初 / 本期收 / 本期支 / 期末」四行，让用户自己能对出来。

### 对 jxc 的含义

- **转账必须是一张有单号的单据，不能是「两个账户各改一笔」的弹窗。** 秦丝的弹窗最省事，但它没有单据号，等于放弃「这笔转账是哪天、谁、为什么」的追溯；星辰、好生意、T+、管家婆都给单据号。jxc 的账本模型要求每笔流水可追溯到一张凭证性单据，转账单必须有号、有日期、有经手人、有备注。
- **手续费只能挂在转出侧，且必须显式进流水。** 星辰的做法（转出金额不含手续费、手续费单独减少账户金额）是唯一能同时满足「两边余额都对」与「手续费可查」的形态；好生意的「差额算手续费」会让人无法区分「手续费」与「转错数」，T+ 干脆没有手续费字段。jxc：转账单上一个 fee 字段，流水生成两条——转出账户记 −(amount+fee)、转入账户记 +amount；不要把手续费单独做成第三条流水，否则一张转账单会变成「转账 + 一笔费用」两件事。
- **「差异」字段是坑，不要抄。** 星辰明文说差异「在账户收支明细上不体现」「单据生成的日记账上也不体现」——这意味着差异是一笔没有流水的账，余额表的合计与流水之和对不上时用户查不出来。jxc 不接受这种暗字段：要么金额相等，要么差额有明确科目（手续费）。
- **转账单的红冲要按普通单据的红冲规则走。** 星辰的四关（未结账、已反审核、无凭证、无日记账）本质是「下游未执行才能删」；若下游已有凭证/日记账，正确动作是另开一张反向转账单而不是删。jxc 选后者（红冲单另取号），与 doc-correction 的结论一致。

## 5. 日常收支单（R5）

### 事实

1. **星辰的资金单据家族是「收 / 付 / 预收 / 预付 / 其他收入 / 其他支出」各自带退款版。** 移动端资金管理菜单列出：收款单、收款退款、预收款单、预收退款、其他收入、其他收入退款、付款单、付款退款、预付款单、预付退款、其他支出、其他支出退款、收款记录、付款记录、客户欠款、供应商欠款、应收账款预警、应付账款预警、收支日结、资金转账单。（金蝶云星辰《【移动应用-应收应付】其他收入、其他支出》，https://vip.kingdee.com/knowledge/647375362934091776?productLineId=35&isKnowledge=2&lang=zh-CN）
2. **星辰的其他收入单必须挂客户，本质是「其他应收」，不是「日常收支」。** 截图表头是「单据编号 / 单据日期 / 客户* / 结算客户* / 部门 / 业务员 / 币别 / 汇率」；表体分「应收」（收入名称、应收金额、税率、不含税金额、税额）与「收款项」（收款账户、收款方式、收款金额、手续费）；官方注：「若还未收到客户的相关款项，收款相关信息可不用填写，表示这笔是应收款。」（同上）

### 对 jxc 的含义

- **「日常收支」必须允许不挂往来单位，否则小店记一笔「买扫把 20 元」要先建供应商。** 好生意用「现金费用 / 现金收入」业务类型解决，网上管家婆用「只填费用项目 + 付款账户」解决，秦丝用账目类型解决；只有星辰把其他收入单做成了客户必填的「其他应收」，这是它的代价（灵活性换应收管理的完整性）。
- **收支项目要独立成档案，且用过只能停用。** 好生意的费用类型/收入类型、秦丝的账目类型、网上管家婆的费用项目都是档案；秦丝明文「一旦被使用，就无法删除，只能停用」——这和 jxc 的「不可变 + 停用」模型天然一致。字段只需要「名称 + 方向（收/支）+ 停用」，分类层级留给 v2。
- **「现结」与「挂账」是一张单的两种状态，不是两张单。** 好生意的做法最干净：同一张其他收入单，填了账号金额就是现结（自动生成收款单），不填就是挂账；网上管家婆同理。jxc：收支单上「账户 + 金额」可空，填了生成资金流水，没填只生成应收/应付。
- **网上管家婆的「调账：资金增加/减少」与期初是两件事，不要合并。** 期初是「启用前的余额」，调账是「启用后发现的差错」（盘点长短款）；jxc 两者都要有，且都应是可追溯的流水，而不是改期初字段。

### 对 jxc 的含义

- **期初是「带日期的余额快照」，不是「一笔金额字段」。** 星辰的期间规则、精斗云的余额日期、T+ 的单位日记账期初都说明这一点：没有日期，期初与流水的先后顺序无法判定，余额就没法算。jxc：opening_balance(account_id, as_of_date, amount)，一张账户可以有多条（换期初时新增一条），最新一条生效。
- **「期初只能启用期间改」这条限制是对账的护栏，jxc 应保留但换实现。** 厂商用「反结账」当护栏，代价是用户为了改一个数要反结账、重结账，很重。jxc 用不可变流水 + 期初调整流水（红冲旧期初、开新期初）实现同样效果，历史可查且不用反结账。
- **期初与报表第一行必须能对上。** 星辰账户余额表有「初始余额」行、精斗云账户列表同时给「期初余额 / 当前余额」；jxc 的余额表首行应显式给「期初余额」，否则用户永远在问「期初去哪了」。
- **别做银行对账期初。** T+ 的「银行对账单期初 + 期初未达 + 余额调节表」是完整出纳方案的一部分，1–3 人店没有这个工作量；v1 只做「账户期初」，银行对账留给需要贷款/审计的场景再说。

### 对 jxc 的含义

- **资金流水的纠错方向是「反向单据」，不是「删原单」。** 除秦丝外，所有厂商都禁止直接改已生效的收付款单，管家婆更把「红冲」设为唯一动作。这与 jxc 的不可变流水天然一致：红冲 = 一张 reversal_of 指向原流水的反向流水，原流水保留，余额自动回退。
- **但「删除未生效单据」要给，且要真删流水。** 好生意的六条前置总结成一句：单据在生效前可以被删，生效后只能弃审；弃审时要检查下游（凭证、核销、锁账、下游单据）。jxc 的阶段划分（草稿 / 生效 / 作废）直接映射：草稿改了不产生流水，生效后改要红冲，作废不是删除。
- **红冲单与退款单是两种东西，别合并。** 退款单是业务（客户真的退钱了），红冲是纠错（这笔收款记错了）。星辰用六种退款单承接业务反向，用反审核+删除承接纠错（只在未生效时）；jxc 两者都要：退款单作为一等业务单据进流水，红冲单作为纠错凭证进流水，两者都另取号。
- **日记账（若做）不能独立于单据存在。** 星辰与 T+ 都因为「日记账可以不来自单据」而长出一堆「不能删」「要先删单据」的规则。jxc v1 不做手工日记账，只做「流水必有单据」；如果以后要导银行流水，那也只能是「未匹配流水」这种明确标记的状态，不能直接改余额。

### 对 jxc 的含义

- **收款单必须同时存「实收」与「核销」两个金额，且允许不等。** 星辰的 38/30/8、T+ 的 1130/1128/2、好生意的折扣分摊、管家婆的 2560/2500，四家都在解同一道题：钱进账户的数和冲应收的数本来就可以不一样。jxc：received_amount（进账户）、allocated_amount（冲应收）、discount_amount（优惠/抹零/折让），约束 allocated = received + discount。
- **折让不进资金流水，但要有独立字段而不是负金额行。** 星辰的优惠金额不是账户收支（账户余额表的取数源只有「业务单据上的账户收支」与「账户初始」），所以折让不产生流水；这正好符合 jxc「资金流水只记真金白银」的口径。用负金额行或改单价去表达折让（doc-fields §5 已否过）会把发票金额、收款金额、应收余额三个数搅在一起。
- **手续费与折让要分开两个字段，不能合成「差异」。** T+ 的手续费会自动生成一张费用单（应收方向），说明手续费在会计上是一笔费用，不是收入的减少；星辰的手续费只减账户金额、不进往来。jxc：手续费减账户余额，同时按需生成一张费用/收支单（可选），折让只减应收、不动账户。
- **退款的方向按「原方向取反」写死，且在资金侧是支出。** 星辰的取数规则（销售退款进支出总额、采购退款进收入总额）给出了标准答案。jxc：退款单的流水方向 = 原收款流水方向 × (−1)，报表上按「流入 / 流出」汇总时自然归位，不需要为退款单单独开一列。

### 对 jxc 的含义

- **默认只提示，不硬拦；硬拦放在「结账 / 日结」或可选参数上。** 精斗云的三段式（记账提醒 → 可继续 → 结账时可设不许结）是成本最低的方案：小店经常「先垫钱后报销」，硬拦会逼用户乱录一张期初或假收款。T+ 的硬拦只出现在付款单这个「主动付款」动作上，也有道理（付款前应该知道没钱）。
- **负余额必须能在余额表上被看见。** 秦丝把 −26 直接显示在账户列表；jxc 的余额表要对负余额高亮，并在首页给一句「现金账户为负」，否则用户永远不知道自己在透支账本。
- **参数只做一个，不做三个。** 好生意的资金管理分组里没有负余额参数，说明这个控制不是小微产品的刚需；jxc v1 给一个 allow_negative_balance（默认 true，仅提示）即可，结账硬拦留给 v2。

## 11. 哪些问题无统一口径

1. **账户类型枚举**：两个固定值（精斗云）、无类型字段（星辰）、类型可选但不参与业务（秦丝）、类型决定必填（好生意：银行才要开户行与账号）。同一件事四种做法。
2. **余额是否物化**：星辰提供「余额重算」、T+ 有 CS_CashAccount 与重算脚本（物化），精斗云、好生意、秦丝、管家婆都表现为「报表或列表现算」。没有一家把余额做成用户可编辑的字段。
3. **余额有几个口径**：星辰两个（账户余额表 / 出纳余额表）、T+ 两个（最新余额 / 实际余额）、其余一家一个。双口径都出现在「出纳模块」存在时。
4. **转账手续费挂哪侧、怎么算**：星辰转出侧独立字段且转出金额不含手续费；好生意一个「手续费/差异」按差额算、可正可负；网上管家婆并进付款额（实际付款 = 收款 + 手续费）；T+ 只有「差异」；秦丝没有手续费。
5. **日常收支是否必须挂往来单位**：星辰其他收入单客户必填；好生意/网上管家婆/秦丝都可以不挂。这直接决定「买扫把」这类支出要不要先建供应商。
6. **期初的载体与可改性**：档案字段（精斗云、管家婆）、独立期初界面（好生意、T+、星辰账户初始数据）、期初调整流水（秦丝）。可改性从「随时可改」到「只能在启用期间改，否则反结账」都有。
7. **退款是独立单据还是负数**：星辰六种退款单、好生意付款单含退款类型；未见厂商用负数收付款单表达退款（T+ 有负数收款单，但官方是当作手续费场景的变通）。
8. **负余额是否拦截**：不拦（秦丝）、只提醒（精斗云）、付款动作硬拦（T+）、未见明文（星辰、好生意、管家婆）。
9. **「资金日报」的定义**：没有一家有一份叫「资金日报」的正式报表；星辰的「收支日结」是待办清单，T+ 只有日记账和对账。
10. **账户能否删除**：星辰可删除也可禁用；秦丝用过不能删只能停用；精斗云未提删除规则。
